# Experience Log — 2026-07-12

## Situation

While organizing a new experience log and working with a GitHub project, I reflected on how preparation, code review, and project organization affect efficiency.

## Lessons learned

### 1. Understand the documentation before taking action

When documentation is available, read and understand it before implementing anything. The time spent understanding the documentation at the beginning is an investment: if the preparation is rushed, the time saved early is often lost later through rework, incorrect assumptions, and repeated debugging.

### 2. Review pull requests carefully

A careful pull request review can significantly improve efficiency. Reviewing the change as a whole—not only checking whether it works—helps catch unclear logic, missing edge cases, unnecessary complexity, and problems that would otherwise become more expensive to fix later.

### 3. Keep the project root clean

The root directory should contain only the files that define or explain the project at a high level. Logs, temporary files, scripts, generated artifacts, and supporting materials should be placed in appropriate subdirectories. A clean root makes the project easier to understand and reduces the time needed to find important files.

## What I would do differently

- Read the relevant documentation before writing or changing code.
- Use pull requests as a deliberate review checkpoint rather than a formality.
- Decide where a new file belongs before adding it to the repository.

## Action items

- [ ] Read the relevant documentation before starting future implementation work.
- [ ] Review every pull request for correctness, clarity, maintainability, and project organization.
- [ ] Keep the repository root limited to essential project-level files.
