# Experience Log — 2026-07-19

## Lessons Learned

### 1. Number and title every table and figure

Every table and figure should have a unique number and a descriptive title. Numbering makes it possible to refer to an item precisely in the surrounding text, while a clear title helps readers understand its purpose without searching through the document.

The numbering should remain sequential and consistent throughout the manuscript. The same convention should be used in the text, captions, table of contents, and cross-references. If a figure or table is added or removed, the numbering and references should be reviewed again.

**Table 1. Formatting consistency checklist / 表 1：格式一致性检查清单**

| Element | Required practice |
| --- | --- |
| Code | Use the project formatter and keep indentation, spacing, and naming consistent. |
| Chinese and English text | Use the defined fonts, sizes, spacing, and punctuation rules consistently. |
| Tables | Use consistent column alignment, borders, captions, and number formats. |
| Headings and captions | Use one hierarchy, numbering scheme, and capitalization style. |

### 2. Apply one formatting system to code and written content

All code should follow one formatting convention. This includes indentation, line breaks, naming style, quote style, spacing, and language-specific formatter rules. Consistent code formatting reduces visual noise and makes review easier.

The same principle applies to Chinese text, English text, tables, headings, captions, and other document elements. Formatting choices such as fonts, font sizes, alignment, line spacing, table borders, and punctuation should be defined before the final editing pass and then applied consistently.

### 3. Describe tests as complete evidence, not isolated numbers

When presenting a test, do not place a result number on the page without context. A useful test record must explain the test conditions, the test content, the result, and the analysis of that result.

**Table 2. Required structure for a test record / 表 2：测试记录的必要结构**

| Section | Question it should answer |
| --- | --- |
| Test conditions | Under what environment, inputs, configuration, and constraints was the test performed? |
| Test content | What procedure, scenario, or behavior was tested? |
| Test result | What was observed, including the relevant measurements and pass/fail status? |
| Result analysis | What does the result mean, what factors affected it, and what should happen next? |

A concise test record can use the following structure:

```text
Test conditions:
- Environment:
- Input or dataset:
- Configuration:
- Constraints:

Test content:
- Procedure or scenario:
- Expected behavior:

Test result:
- Observation:
- Measurement:
- Status:

Result analysis:
- Interpretation:
- Limitations:
- Next action:
```

For example, “The response time was 320 ms” is incomplete by itself. A reader needs to know what was tested, under which conditions, whether 320 ms met the target, and what conclusion can reasonably be drawn from the measurement.

## 经验总结

### 1. 为每一张表格和图片编号并添加题目

每一张表格和图片都应有唯一编号和清晰的题目。编号可以让读者在正文中准确引用对应内容，清晰的题目则能让读者无需反复查找就理解其用途。

编号应在整篇原稿中保持连续和一致。正文、题注、目录和交叉引用应使用同一套编号规则。如果新增或删除图片、表格，应重新检查编号及其引用关系。

**表 1：格式一致性检查清单 / Table 1. Formatting consistency checklist**

| 要素 | 要求 |
| --- | --- |
| 代码 | 使用项目统一的格式化工具，保持缩进、空格和命名风格一致。 |
| 中文与英文文本 | 统一使用规定的字体、字号、间距和标点规则。 |
| 表格 | 统一列对齐方式、边框、题注和数字格式。 |
| 标题与题注 | 统一层级、编号方式和大小写风格。 |

### 2. 统一代码和书面内容的格式体系

所有代码都应遵循统一的格式约定，包括缩进、换行、命名风格、引号风格、空格以及语言对应的格式化工具规则。统一的代码格式可以减少视觉干扰，也能让审查更加容易。

同样的原则也适用于中文、英文、表格、标题、题注以及其他文档元素。字体、字号、对齐方式、行距、表格边框和标点等格式选择应在最终编辑前确定，并在全文中保持一致。

### 3. 将测试描述为完整证据，而不是孤立数字

阐述测试时，不能脱离上下文直接放置一个结果数字。一份有用的测试记录必须说明测试条件、测试内容、测试结果以及结果分析。

**表 2：测试记录的必要结构 / Table 2. Required structure for a test record**

| 部分 | 应回答的问题 |
| --- | --- |
| 测试条件 | 测试是在什么环境、输入、配置和约束下进行的？ |
| 测试内容 | 测试了什么流程、场景或行为？ |
| 测试结果 | 观察到了什么，包括相关测量值和通过/失败状态？ |
| 结果分析 | 结果意味着什么，哪些因素影响了结果，下一步应该做什么？ |

简洁的测试记录可以采用以下结构：

```text
测试条件：
- 环境：
- 输入或数据集：
- 配置：
- 约束：

测试内容：
- 流程或场景：
- 预期行为：

测试结果：
- 观察结果：
- 测量值：
- 状态：

结果分析：
- 解释：
- 局限性：
- 后续行动：
```

例如，“响应时间为 320 毫秒”本身是不完整的。读者还需要知道测试了什么、在什么条件下测试、320 毫秒是否达到目标，以及根据该测量值可以合理得出什么结论。
