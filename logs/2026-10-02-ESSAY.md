# Attention 总结（2026-10-02）

## 1.Attention 的过程可以这样写：
当前 token 在这一层的 hidden state 是 `h_i`。先经过 RMSNorm，稳定向量的数值尺度：
`h̃_i = RMSNorm(h_i)`
再通过三个不同的线性投影，生成 Query、Key、Value：
`q′_i = h̃_i × W_Q`
`k′_i = h̃_i × W_K`
`v_i = h̃_i × W_V`
其中：
`q′_i`：当前 token 用来“查询”的特征；
`k′_i`：当前 token 提供给别人匹配的特征；
`v_i`：当前 token 真正携带的信息。
接着对 Query 和 Key 加入位置信息：
`q_i = RoPE(q′_i, i)`
`k_i = RoPE(k′_i, i)`
这样，Query 和 Key 不仅包含 token 内容，也包含 token 在序列中的位置。
当前 token 的 Query 会和每个历史 token 的 Key 计算匹配分数：
`s_ij = (q_i × k_jᵀ) / √d`
分数越大，表示当前 token 越关注历史 token `j`。
然后对所有分数做 softmax：
`α_ij = softmax(s_ij)`
得到 attention weight，最后用这些权重加权历史 Value：
`output_i = Σ_j α_ij × v_j`
所以完整过程是：
`h → RMSNorm → Q, K, V → RoPE(Q, K) → QKᵀ → softmax → Σ αV`
其中，KV cache 保存的是历史 token 的 `K` 和 `V`，让新的 Query 可以直接和它们匹配。

## 3.KVQuant
KVQuant 主要是在做 KV cache 的低比特量化，目的是减小长上下文下 KV cache 的内存占用和 decode 时的带宽压力。它先分析 K/V 的分布，发现 Key 更适合 per-channel quantization，Value 更适合 per-token quantization。Key 在 RoPE 前 channel-wise distribution 更稳定，所以作者选择 pre-RoPE Key quantization；但这样会增加 dequantization + RoPE 的 runtime 开销，因此又通过 fused kernel 解决。
另外它把 SqueezeLLM 的思路搬到了动态 KV activation 上：weighted k-means / sensitivity 这种昂贵步骤放到 offline calibration 做，runtime 只需要用预先得到的 non-uniform quantization signposts。KV 里也有 outlier，但因为不同 channel/token 的平均 magnitude 不一样，所以不能简单全 layer 一起找，而是做 per-vector Dense-and-Sparse：Key 按 channel，Value 按 token 找 outlier。(其实没咋看完 以后有机会再看吧)
