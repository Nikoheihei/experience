## CPU和GPU的差别
  cpu的线程相较于gpu的线程来说少很多。
  cpu的目的是降低latency，而gpu的目的是增大吞吐。

## GPU内部
  ·GPU内有很多个SM（streaming multiprocessors）execute blocks
  ·内存离SM越近，访存更快。L1 inside SM。L2 cache在硅片上。gpu通过HBM和DRAM连接。
  ·blocks are groups of threads and share same memory but different inputs. one SM takes one block.
   Threads可以并行
   当线程执行时，通常会以组的形式进行，这里的组成为warp。
  ·每个线程可以访问自己的register和shared memory within the block但是如果要访问的数据在不同的block里，那么需要去global memory里读/写。
  ·compute的scale速度远比memory的scale速度快，因此对于memory的设计非常重要。

## TPU
  tensor core(类似GPU里的SM)只做矩阵乘法

## 如何让GPUs运行地快
  
### 1.control divergence:SIMT(single instruction multi thread):

  一个warp里的所有thread必须执行同一个指令。因此如果有一个if-else语句将thread分为A和B两组，A和B组的线程不会同时进行而是依次执行

### 2.(以下的方法都基于memory)low precision:

  减少保存的精度可以有效减少bytes/Flops的数值

### 3. kernel fusion:

  如果要对一条数据进行多次compute操作，尽量一次compute完再把最后结果搬回memory，而不是反复把中间结果来回在compute和memory之间搬。（torch compile？）

### 4. recomputation:

  在反向计算时，或许不用存储前向计算的中间值，而是重新计算一次前向计算从而减少memory读取的次数且减少对bandwidth的压力。

### 5.memory coalescing and DRAM

  burst mode: 查0位，给0123位
  memory coalescing:同一个warp内的所有线程同时访问同一burst内的数据。如果不同thread是从左往右读那么就不是memory coalesce（因为不同thread同时访问的数据位于不同行），如果不同thread从上往下读，此时不同thread同时访问的数据位于同一列，因此是memory coalesce。

### 6. tiling

  把一个大的矩阵分成很多个子矩阵，同时把子矩阵读到共享内存里，减少global memory的等待时间。

  tiling可能的问题：1.某个子矩阵内部非常的稀疏。2.tile的尺度和burst mode的尺度不对齐-padding（大的矩阵如果是32的倍数会比2的倍数好之类的）。3.tile的总数和gpu内的SMs数量关系可能会出现gpu利用率断层下降的现象(wave quantization)。eg. 120tile & 98 SMs

## FlashAttention快的原因

  1.tiling for the KQV matrix multiply

  2.online softmax（真烧脑了。。看完已力竭。）：softmax计算x的时候要减去不同x的最大值，这样e^x的结果都在0～1之间不会溢出。这里利用两个e^x相乘等于指数相加的性质。

  3.在反向传播计算的时候，重新按tile计算。
